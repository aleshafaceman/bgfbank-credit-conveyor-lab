# Словарь БЖФ

## Объекты

| Термин | Что это |
|--------|---------|
| **Лид** (потенциальный клиент, Lead) | Короткая заявка: канал, продукт, прескоринг, ответственные. Ещё не полный конвейер банка. |
| **Заявка / сделка** (Sale, full application) | Полный объект после `CreateFullApplication`. Номер вида `25BGFB…`. |
| **Заёмщик** | MAIN — основной; CO_BORROWER — созаёмщик (супруг / родственник / иное). У каждого свой контур заполнения / СБ / АНД. |
| **Залог / продукт** | Объект недвижимости в заявке. Тип: квартира, апартаменты, доля, дом, таунхаус, коммерция, земля, гараж. |
| **Офер** | Пакет Solver на входе (сумма, ставка, LTV). Не решение АНД. |
| **ДУ** | Дополнительное условие из `ElmaAdditionalConditionTypeEnum` (0–18). Источник — решение АНД/АПЗ. `when`: `signing` (снять до подписи КОД) или `issue` (на выдачу/аккредитив; тип 14 — «Погашение после сделки»). |
| **КОД** | Комплект документов на сделку. Готовит процессор КОД (ОПС) после паспорта. Подписание КОД ≠ заявление на счёт ≠ заявление на ДБО. |
| **Снимок сделки** | Машиночитаемый JSON+файлы в момент «КОД сформирован». Источник правды для офиса. `deal_id` = номер заявки. |
| **Паспорт сделки** | Слот: дата/время, форма расчётов, тип подписания, закладная, подписант банка. Барьер: клиент **и** залог одобрены. Не экран `deal-ops` v1. |
| **РКО / счёт** | Розничный счёт в ЦФТ. Статус: `none` \| `reserved` (к подписанию, ещё не открыт — проверки и заявление нужны) \| `open` (без заявления на открытие). |
| **ДБО** | Дистанционное банковское обслуживание. Заявление на ДБО + приложение 1 (безакцепт) — отдельный документ. СМС после открытия счёта. |
| **СОПД** | Согласие на обработку ПДн. Первое: `short` \| `full`. В `cabinet` каналы на шаге 1: `by_esia` (Госуслуги), `by_questionary` (анкета SMS), `by_uploaded_consent` (бумага, только менеджер). Для сделки нужна `full`. Отдельного согласия на счёт нет. |
| **`deal-ops`** | Sidecar strangler этапа 4: офис после КОД. Потом тот же bounded context входит в Conveyor. |
| **КВ** | Комиссия партнёра. Хвост strangler (этап 5), не конвейер выдачи. Актуальные % — [partner-offer.md](partner-offer.md); внутренний рефин без КВ. |
| **«Зелёный коридор»** | Опция для сложной КИ (залог / покупка / рефин в банке). Не отдельная цель кредита в enum. |
| **Госключ** | Подписание УКЭП в приложении Госуслуг. Партнёрский канал электронной сделки; не адаптер SmartDeal. |
| **ЮЛ-заёмщик** | Кредит ИП/ООО/АО/ПАО под залог. Не путать с ЮЛ-партнёром в регистрации кабинета. |

## Продукты (`CreditPurposeEnum`)

| Код | Смысл |
|-----|--------|
| `mortgage` | Покупка (объекта на входе может не быть). Витрина партнёра: «кредит на приобретение». |
| `cash_on_pledge` | Кредит под залог недвижимости (нецелевой / ремонт / иное; апартаменты, коммерция ФЛ, «купи ставку»). |
| `refinancing` | Рефинансирование. Внутреннее (`BankOfRefinancingEnum.bgf`) — без КВ. |

Маркетинговые имена и ставки «от X%» — [partner-offer.md](partner-offer.md), не новые значения enum.

Подтверждение дохода в банке: Standard / Light и линейка Solver (`universal_hiring`, `universal`, `express`, `express_plus`) — разные слои, не синонимы без проверки кода. Справка по форме банка / выписка / СЗИ-ИЛС / НДФЛ — слой банка для партнёра.

Категория КИ **К1–К5** приходит **после АНД** (Loginom / ELMA), Solver на входе её не знает.

`signing_channel`: `paper` \| `smartdeal` — вид сделки за столом, не этап Росреестра. Госключ в презентации партнёрам — отдельный канал УКЭП, в enum стола v1 его нет.  
`account_open_when`: `before_kod` \| `after_kod` — счёт до или после подписи КОД (Visio).  
`disbursement`: `before_state_registration` \| `after_state_registration`.

## Роли AS-IS / TO-BE

| Роль | Что делает |
|------|------------|
| Партнёр / брокер | Кабинет B2B `/`: лид, документы, офер, сопровождение доработки. На шаге 1 заёмщика — Госуслуги или анкета SMS, без «Заполнить вручную» |
| Сейл / КЦ / сотрудник продаж | Банковский канал. В том же `cabinet` вход `/manager`: видит чужие заявки, выбирает партнёра, может заполнить заёмщика вручную (OCR + бумажное СОПД) |
| Процессор (заёмщик / залог / КОД / ОПС) | Комплект, данные, подготовка КОД |
| АНД | Андеррайтинг заёмщика |
| АПЗ | Андеррайтинг залога |
| СБ | Проверка всех заявок, лимит циклов доработки |
| Структуратор | Коррекция после одобрения |
| КК | Кредитный комитет (permission, не отдельный логин) |
| ОЗС (`deal_officer`) | Паспорт сделки; в офисе после КОД — сверка паспорта со снимком, СОПД, ДУ, заявление РКО, подписание КОД, ДБО. Клиент **не** уходит во второе окно |
| ОПЕРУ (`operu`) | **Exception desk** автопроверок открытия счёта. Не идентификация и не набор клиента с нуля |
| ОБУКО / ЦФО (`cfo_obuko`) | Правка клиента в ЦФТ (`CorrectPassportData`); выдача на уже открытый счёт. В `deal-ops` v1 экрана нет |
| Оценщик банка | Верификация оценки; независимый оценщик — загрузка отчёта |

В текущем ЛК есть `partner` и `manager` (два входа одного SPA, [cabinet.md](cabinet.md)). Ролей АНД/СБ/ОЗС в ЛК нет.

## Каналы

| Канал | Как входит |
|-------|------------|
| B2B / брокер | `cabinet` `/` (https://lk.bgfbank.ru, препрод https://pp.bgfbank.ru/) → ELMA `CreateLead` / `CreateFullApplication` |
| Интернет-заявка / сайт / сравни.ру / банки.ру | Reception / форма подачи. В гриде менеджера такие лиды видны с создателем/партнёром |
| КЦ / офис | сейл от имени клиента; тот же `cabinet` `/manager` |
| CIAN | `cian` + Reception |

TO-BE `channel` на агрегате: `b2c` / `leadgen` / `sales`. `partner` — только легаси, пока жива ELMA.

`route_mode`: **split** — заёмщик и залог собираются раздельно; **combined** — один клиентский вход (залог своей квартиры, кадастр + ЕГРН, один объект, без созаёмщика). Экспертиза банка в combined всё равно две очереди (АНД и АПЗ).
