Виджет
REST API
REST API позволяет получать информацию о вашем аккаунте, лидах (контактах), звонках
и записях разговоров.
API доступно по протоколу HTTPS по url
https://api.skorozvon.ru/api/v2
Ограничения
Ограничения по количеству запросов- 10 запросов в секунду.
При превышении лимита запросов сервер вернет HTTP-статус 429.
Авторизация
Для авторизации запросов используется протокол OAuth 2.0.
При взаимодействии сервер-сервер, ключ авторизации можно получить с помощью
режима “Password Credentials”.
Необходимые реквизиты для авторизации можно получить на странице
https://app.skorozvon.ru/#settings/integration/api.
Пример запроса ключа авторизации с использованием утилиты curl
curl https://api.skorozvon.ru/oauth/token \-X POST \-F grant_type="password" \-F username="e-mail пользователя" \-F api_key="API-ключ" \-F client_id="ID приложения" \-F client_secret="Ключ приложения"
Параметр grant_type="password" передается прямо в таком виде, вставлять в него
пароль пользователя не нужно.
В ответ на запрос придет JSON-документ. Необходимо извлечь из него access_token.
Полученный access_token необходимо подставлять в запросы, в заголовок Authorization с
указанием типа токена- Bearer.
Для скачивания записей звонков, авторизация через заголовок Authorization не
поддерживается. Необходимо передавать access_token как параметр URL
Пример
curl https://api.skorozvon.ru/api/v2/leads \-H "Authorization: Bearer {access_token}"
Выданный access_token действителен 2 часа. Если взаимодействие предусматривает
переиспользование ключа авторизации, его необходимо продлевать.
Для продления ключа авторизации необходимо использовать refresh_token, полученный в
ответе на запрос ключа авторизации.
Пример
curl https://api.skorozvon.ru/oauth/token \-X POST \-F grant_type="refresh_token" \-F refresh_token="{refresh_token}" \-F client_id="ID приложения" \-F client_secret="Ключ приложения" \-H "Authorization: Bearer {access_token}"
Авторизация по постоянному ключу
Данный токен может быть получен через службу поддержки. На текущий момент
применяется только для отчетов .
Для получения данных по конкретному отчету нужно отправить POST запрос с
использованием токена.
Пример
curl https://api.skorozvon.ru/api/reports/calls_total.json \-X POST \-H 'Content-Type: application/json' \-H 'Authorization: Key #{endless_token}'

Массовое удаление лидов
POST /api/v2/leads/bulk_deletes
Используйте данный метод для массового удаления лидов, операция асинхронная, в
ответе будет выдан идентификатор массового удаления, по которому при необходимости
можно проверить состояние через метод GET /api/v2/bulk_deletes/{id}
Тело запроса должно быть в формате JSON, например:
{"ids": [12282518, 12282519, 12282520, 12282521]}
GET /api/v2/bulk_deletes/{id}
Получение состояния массового удаления данных
Состояния процесса массового удаления (поле "state"):
created: Удаление находится в очереди на обработку:
processing: Удаление запущено.
finished: Удаление завершено.
В случае завершения массового удаления с ошибкой, в ответе будет выдан флаг
"errors": "Операция завершилась с ошибкой"
Массовая загрузка
POST /api/v2/leads/import
Массовое создание лидов.
Операция асинхронная, в ответ будет выдан идентификатор загрузки, по которому при
необходимости можно проверить состояние через метод GET /api/v2/leads/import/{id}.
Ограничения
Ограничения по количеству запросов- 1 запрос в 30 секунд.
Тело запроса необходимо передавать в формате JSON.
Например:
{"call_project_id":12345,"data":[{"name":"Тестовый контакт","phones":["+79123456789"]}]}

GET/api/v2/calls
Позволяетполучитьсписоквызововспостраничнойнавигацией.
Параметрызапроса
Поле Тип Описание
start_time unixtime Фильтрациявызововначинаясзаданной
даты-Еслипараметрнепереданвответебудут
вызовызапоследнийдень
end_time unixtime Фильтрациявызововдозаданнойдаты-Еслипараметрпередан,нонезадано
значениеstart_time- вответебудутвызовы
заденьотзаданнойдаты
organization_id integer Фильрациявызововпоконкретной
организации
sort_by_start boolean Сортировкавызововповремениначала
звонка
sort_by_start: true
sort_direction string Порядоксортировки:-ASCдлясортировкиповозрастанию-DESCдлясортировкипоубыванию
Дляболееудобнойиэффективнойработысданныминеобходимофильтроватьвызовы,
начинаясзаданнойдаты,используяпараметрstart_time:unixtime.
Чтобыполучитьсписоквызововтолькопоконкретнойорганизации,используется
параметрorganization_id:integer.
Еслипереданorganization_id:integerипустойstart_time:unixtimeвответебудутвсезвонки
попроекту,безограниченияповремени.
Для настройки сортировки результирующего списка звонков используются
необязательные параметры sort_by_start:boolean и sort_direction:string. При передаче
sort_by_start: true, результаты будут упорядочены по времени начала звонка. Параметр
sort_direction позволит выбрать порядок сортировки: ASC для сортировки по возрастанию
и DESC для сортировки по убыванию.
Пример:
https://api.skorozvon.ru/api/v2/calls?start_time={start_time}&organization_id={organization_id}&
sort_by_start=true&sort_direction=DESC
Предоставит список вызовов организации {organization_id}, начиная с {start_time},
отсортированный по дате начала звонка (started_at) от новых к старым.

Запрос для выгрузки архива записей осуществляется на URL <имя отчёта>/records. К
примеру, для выгрузки архива записей из отчёта по всем вызовам необходимо
обратиться с указанными параметрами на URL
https://api.skorozvon.ru/api/reports/calls_total/records
В зависимости от объёма данных в переданном в запрос периоде, на ответ сервера
может потребоваться длительное время, что следует учитывать при разработке
клиентского приложения. Стандартный таймаут запроса равен 5 минутам. Если в течение
этого времени сервер не смог вернуть данные, следует сменить параметры запроса (к
примеру, сократить запрашиваемый интервал).
В случае успешного выполнения запроса, ответ с HTTP-статусом 200 будет содержать
JSON-объект с единственным ключом:

Содержащиеся в ответе URL можно опрашивать с некоторыми интервалами до
получения успешного ответа. Время их жизни составляет 30 минут, максимальное время
выполнения задачи по формированию архива также равно 30 минутам. Если в течение
этого времени не удалось успешно получить файл по сгенерированным URL, то
процедуру следует начать сначала, модифицировав параметры запроса.
Если для запрашиваемого отчёта недоступна выгрузка архива записей, такого отчёта не
существует в сервисе, либо доступ к нему запрещён для пользователя, от имени которого
выполняется запрос, будет отправлен код ответа 403 Forbidden.
Webhooks
Webhooks- это механизм уведомления внешних систем об изменениях, произошедших в
Скорозвоне. На заданный в системе URL по протоколу HTTP отправляется информация,
связанная с событием.
Отправляются следующие виды событий:
● Сохранение результата звонка (call_result). Содержит информацию о лиде, звонке
и результате звонка
● Сохранение анкеты (form_response). Содержит информацию о лиде, звонке и
заполненных полях анкеты
● Неуспешный обзвон лида по проекту (call_project_case_failed). Содержит
информацию о лиде и проекте
Важно!
Сохранение анкеты (form_response) отправляет данные о звонке на текущий момент, если
webhook отправлен до сохранения результатов звонка, данные о звонке могут
отличаться.
Рекомендуется для получения корректных данных о звонке, использовать webhook
Сохранение результата звонка (call_result).
Первая попытка отправки веб-хука происходит сразу после совершения действия.
Если первая попытка не удалась, производятся еще 5 попыток с увеличением интервала:
5 минут, 30 минут, 1 час, 3 часа, 6 часов.
Ошибкой считается любой HTTP-статус ответа на запрос с кодом более 400
(включительно) или таймаут исполнения запроса.
Вебхук отключается, если получено 50 ошибок и больше.
Возможные ошибки:
● Ошибки на стороне сервера
● Превышены таймауты на выполнение операций:
Имеется следующие таймауты:
● на открытие соединения- количество секунд ожидания открытия соединения,
данное значение равно 5 секундам
● На отправку данных- количество секунд ожидания для отправки данных, данное
значение равно 10 секундам.
Для корректной обработки повторов на вашей стороне, мы передаем в запросе HTTP
заголовок Idempotency-Key. Для каждого события он содержит уникальное значение. Все
повторные запросы осуществляются с этим же значением.
Для обеспечения безопасности рекомендуется использовать протокол HTTPS и ключи
для авторизации (могут настраиваться на нашей стороне, например через передачу
HTTP-заголовка Authorization).
Тело запроса представлено в формате JSON.

агрегироваться и отсылаться пачкой. Таким образом, вместо50запросовквашемусерверу

Виджет
Требования к виджету:
Браузер: IE8+, Opera 9+, Firefox *, Safari 4+, Chrome 2+
Adobe Flash Player 11.2+
Пример вставки виджета
<html>
<head>
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<script type="text/javascript" src="https://widget.skorozvon.ru/phone.js"></script>
<style>
body {
margin: 0;
padding: 0;
height: auto;
width: auto;
overflow: hidden;
}
</style>
<script type="text/javascript">
Tube.ready = function() {
phoneWidget = new Tube.Widgets.Phone({
el: "#widget", // элемент на странице, в который размещается виджет
waitActiveCall: false, // при значении true- активный звонок(или несколько) ждет пока
оператор завершит разговор и сохранит карточку
disallowNormalStateOnActiveCall: false, // при значении true- запрет на изменение статуса на
"Доступен" при открытой карточке (чтобы диалер не распределял на пользователя, пока открыта
карточка)
});
phoneWidget.phoneModel.on('call:started', function(call) {
// обработка события инициализации звонка
});
phoneWidget.phoneModel.on('call:ringing', function(call) {
// обработка события начала дозвона
});
phoneWidget.phoneModel.on('call:connected', function(call) {
// обработка события соединения звонка
});
phoneWidget.phoneModel.on('call:ended', function(call) {
// обработка события завершения звонка
});
/// во всех случаях в аргумент call попадает Backbone-модель
/// объекта звонка. Её атрибуты доступны с помощью метода .get(attr)
/// call.get('lead_external_id') => получить external_id контакта верхнего уровня, которому
совершается звонок
document.getElementById("make_call").addEventListener("click", function() {
/* makeCall(phone:number, params:{});
объект params принимает ключи:
lead_id: number|null, // id организации или контакта из скорозвона.
deferred_transfer_phone: string|null //- валидный номер, который подставляется в
поле номера для переадресации
*/
phoneWidget.makeCall("+79221234567");
});
/*
пример перевода текущего вызова
phoneWidget.transferCurrent({
user_id: <integer>,-- перевод на определённого пользователя
phone_user_group_id: <integer>,-- перевод на группу пользователей. Информация о
существующих группах доступна в GET /api/v2/user_groups
number: <string>,-- перевод на определённый номер
consultation: <boolean>-- начать перевод с консультацией
});
в случае отсутствия текущего вызова попытка перевода не произойдёт
*/
phoneWidget.login({
email: "e-mail зарегистрированного пользователя",
api_key: "api-ключ"
});
phoneWidget.show();
}
</script>
