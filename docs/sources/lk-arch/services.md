## 1. auth - Сервис аутентификации

### Назначение
Централизованный сервис аутентификации и авторизации для всех микросервисов системы. Выдает JWT токены для межсервисного взаимодействия.

### Технологии
- FastAPI
- JWT токены
- Redis (опционально, для хранения сессий)

### Основные функции
- Выдача токенов доступа для сервисов
- Валидация токенов
- Управление приложениями (app_id, secret)

### API Endpoints

#### `POST /api/auth`
Получение токена авторизации для сервиса.

**Запрос:**
```json
{
  "app_id": "partner_api",
  "secret": "jt9faDXK0q"
}
```

**Ответ:**
```json
{
  "auth_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "deltas": [0.001, 0.002, 0.003],
  "total": 0.006
}
```

#### `GET /api/ping`
Проверка валидности токена (защищенный endpoint).

**Заголовки:**
- `x-token`: JWT токен

**Ответ:** `"pong"` или ошибка 401/404

### Конфигурация

Файл: `bgf-backend/auth/config/config.yml`

Основные параметры:
- `apps` - список приложений с их `app_id` и `secret`
- `token_expiration` - время жизни токена

### Модели данных

**AppModel** - модель приложения:
- `app_id` - идентификатор приложения
- `secret` - секретный ключ
- `token` - JWT токен

### Интеграция

Все сервисы используют `auth` API для:
- Получения токенов при старте
- Валидации токенов в middleware
- Проверки прав доступа

### Особенности

- Легковесный сервис без базы данных
- Использует конфигурационные файлы для хранения приложений
- Токены имеют ограниченное время жизни
- Поддержка множественных приложений

## 2. solver - Сервис расчета кредитных решений

### Назначение
Расчет кредитных предложений (оферов) на основе параметров заявки: региона, кредитной истории, типа недвижимости, суммы кредита и других факторов.

### Технологии
- FastAPI
- PostgreSQL (для хранения банков и регионов)
- JSON конфигурации (loan_settings.json, атрибуты LTV)
- Система условий (ConditionsResolver)

### Основные функции
- Расчет кредитных предложений
- Определение LTV (Loan-to-Value) в зависимости от множества факторов
- Фильтрация оферов по условиям
- Получение списка доступных регионов
- Расчет программ кредитования

### API Endpoints

#### `POST /calculator/`
Расчет списка оферов для заданных параметров.

**Запрос:**
```json
{
  "application_id": "uuid",
  "product_category": "CASH_ON_BAIL",
  "credit_history": "K1",
  "property_type": "FLAT",
  "building_price": 10000000,
  "region_kladr_id": "7700000000000",
  "loan_amount": 5000000,
  "loan_term": 120
}
```

**Ответ:**
```json
[
  {
    "code": "bgf_loan_simple",
    "rate": 12.5,
    "minInitialPayment": 0.3,
    "maxAmount": 7000000,
    "minTerm": 12,
    "maxTerm": 240,
    "requirements": [...]
  }
]
```

#### `POST /calculator-cian/`
Специальный endpoint для расчета оферов для CIAN (формат Application).

#### `POST /programs/`
Получение программ кредитования с требованиями.

#### `POST /regions`
Получение списка доступных регионов для продукта.

#### `GET /loan-settings/`
Получение текущих настроек кредитных продуктов.

### Конфигурация

**Основные файлы:**
- `etc/loan_settings.json` - базовые настройки продуктов
- `etc/jsonc/products/enabled/` - активные продукты
- `etc/jsonc/attributes/` - 38 файлов LTV атрибутов

**Версионирование:**
- `etc/versions/2024-09-17/loan_settings.json`
- `etc/versions/2024-11-03/loan_settings.json`

### Модели данных

**LoanProductSettings** - настройки продукта:
- `code` - код продукта
- `base_rate` - базовая ставка
- `rates_by_credit_history` - ставки по кредитной истории
- `ltv_settings` - настройки LTV

**Offer** - кредитное предложение:
- `code` - код продукта
- `rate` - процентная ставка
- `minInitialPayment` - минимальный первоначальный взнос
- `maxAmount` - максимальная сумма кредита
- `minTerm`, `maxTerm` - сроки кредита
- `requirements` - требования к заемщику

### Система LTV

LTV рассчитывается на основе:
1. **Региона**: Москва, МО, СПб, ЛО, регионы
2. **Кредитной истории**: K1 (57-70%), K2 (52-65%), K3 (40-65%), K4 (40-60%), K5 (35-57%)
3. **Типа недвижимости**: квартира, апартаменты, коммерческая
4. **Расстояния до МКАД/КАД**: для МО и ЛО
5. **Специальных условий**: первый этаж, "Кредит для своих"

Подробнее: [LTV_Analysis_solver_api.md](../../LTV_Analysis_solver_api.md)

### Интеграция

- **partner API**: основной потребитель для расчета оферов
- **cian**: использует `/calculator-cian/` endpoint
- **reception**: использует для расчета решений по заявкам

### Особенности

- Сложная система условий для расчета LTV
- Поддержка множества кредитных продуктов
- Динамическая конфигурация через JSON файлы
- Версионирование настроек
- Кэширование результатов расчетов

## 3. partner - API для партнеров

### Назначение
Основной API для работы партнеров банка с заявками, клиентами, документами, продуктами и финансовыми операциями.

### Технологии
- FastAPI
- PostgreSQL (Alembic миграции)
- Redis (кэширование, очереди)
- RabbitMQ (уведомления)
- WebSocket (real-time уведомления)
- Celery (фоновые задачи)
- SQLAlchemy 2.0 (async)

### Основные функции
- Управление заявками (applications)
- Работа с заемщиками (borrowers)
- Загрузка и обработка документов
- Интеграция с recognition API для OCR
- Интеграция с consent API для согласий
- Управление продуктами
- Финансовые операции
- Интеграция с ELMA CRM
- Уведомления через WebSocket
- Аналитика и отчеты

### API Endpoints

#### Заявки (Applications)

**`POST /applications`** - Создание новой заявки
**`GET /applications`** - Список заявок (с фильтрацией)
**`GET /applications/{id}`** - Получение заявки
**`PUT /applications/{id}`** - Обновление заявки
**`POST /applications/{id}/send`** - Отправка заявки на обработку
**`POST /applications/{id}/bring_to_underwriting`** - Перевод в андерайтинг

#### Заемщики (Borrowers)

**`GET /borrowers`** - Список заемщиков
**`GET /borrowers/{id}`** - Получение заемщика
**`PUT /borrowers/{id}`** - Обновление заемщика
**`POST /borrowers/{id}/documents`** - Прикрепление документов
**`POST /borrowers/{id}/consent`** - Создание согласия

#### Документы (Documents)

**`POST /files/upload`** - Загрузка файла
**`POST /files/upload/list`** - Загрузка нескольких файлов
**`GET /files/{id}`** - Получение файла
**`POST /documents/{id}/recognize`** - Распознавание документа
**`GET /documents/{id}/recognition`** - Статус распознавания

#### Продукты (Products)

**`POST /products`** - Создание продукта
**`GET /products/{id}`** - Получение продукта
**`PUT /products/{id}`** - Обновление продукта
**`POST /products/{id}/appraisal`** - Запрос оценки недвижимости
**`POST /products/{id}/recognize_egrn`** - Распознавание ЕГРН

#### Аутентификация

**`POST /auth/cell`** - Получение SMS кода
**`POST /auth/pass`** - Авторизация по SMS коду
**`POST /auth/hash`** - Авторизация по hash (для согласий)

#### Уведомления

**`WebSocket /notifications/{token}`** - Подключение к уведомлениям

#### Административные

**`POST /adm/proxy/request`** - Прокси запросы
**`GET /adm/files`** - Список файлов (админ)
**`POST /adm/migrations/upgrade`** - Применение миграций

### Модели данных

**ApplicationModel** - заявка:
- `id` - UUID
- `status` - статус заявки
- `partner_id` - ID партнера
- `created_at`, `updated_at` - временные метки
- `product` - связанный продукт
- `borrowers` - список заемщиков

**BorrowerModel** - заемщик:
- `id` - UUID
- `first_name`, `last_name`, `middle_name` - ФИО
- `passport_series`, `passport_number` - паспорт
- `mobile_phone` - телефон
- `documents` - связанные документы

**ProductModel** - продукт:
- `id` - UUID
- `application_id` - ID заявки
- `property_type` - тип недвижимости
- `building_price` - стоимость недвижимости
- `loan_amount` - сумма кредита

**DocumentModel** - документ:
- `id` - UUID
- `document_type` - тип документа
- `files` - связанные файлы
- `recognition` - данные распознавания

### Статусы заявки

- `FILL_IN` - заполняется
- `PRIOR_PROCESSING` - предварительная обработка
- `PRIOR_APPROVE` - предварительно одобрена
- `PRIOR_FAIL` - предварительно неодобрена
- `APPLICATION_SENT` - заявка отправлена
- `UPLOAD_DOCUMENTS` - подготовка документов
- `PROCESSING` - обрабатывается
- `ACCEPTED` - одобрена
- `DECLINE` - отказ

### Интеграции

**recognition API:**
- Создание задач на распознавание
- Проверка статуса распознавания
- Получение результатов OCR

**consent API:**
- Создание согласий
- Отправка подготовленных согласий
- Получение данных клиентов

**solver API:**
- Расчет кредитных предложений
- Получение программ кредитования

**ELMA CRM:**
- Отправка заявок в ELMA
- Получение статусов из ELMA
- Синхронизация документов

### Конфигурация

Файлы в `partner_api/etc/`:
- `config.yml` - основная конфигурация
- `database.yml` - настройки БД
- `recognition.yml` - настройки recognition API
- `consent.yml` - настройки consent API
- `solver.yml` - настройки solver API
- `elma.yml` - настройки ELMA
- `notifications.yml` - настройки уведомлений

### Особенности

- Поддержка множественных партнеров
- Система ролей и прав доступа
- Real-time уведомления через WebSocket
- Интеграция с внешними системами
- Поддержка фоновых задач через Celery
- Миграции БД через Alembic

## 4. reception - Сервис приема заявок

### Назначение
Прием заявок от различных источников (веб-формы, интеграции), создание лидов и заявок в partner API, интеграция с ELMA CRM и AmoCRM.

### Технологии
- FastAPI
- PostgreSQL (async, SQLAlchemy 2.0)
- Redis
- RabbitMQ
- Celery
- Alembic (миграции)

### Основные функции
- Прием заявок (submissions)
- Создание лидов (leads)
- Интеграция с ELMA CRM
- Интеграция с AmoCRM
- Интеграция с Call Center
- Обработка email-лидов
- Отправка постбеков
- Административные функции

### API Endpoints

#### `POST /submission/`
Прием заявки от внешнего источника.

**Запрос:**
```json
{
  "borrower": {
    "firstName": "Иван",
    "lastName": "Иванов",
    "mobilePhone": "+79991234567"
  },
  "loanParameters": {
    "loanAmount": 5000000,
    "loanTerm": 120
  },
  "source": "WEB_FORM"
}
```

**Ответ:**
```json
{
  "status": "CONFIRM"
}
```

#### `GET /status`
Получение статуса заявки по ID.

#### `POST /admin/leads`
Административные функции для работы с лидами.

#### `GET /amocrm/integrations`
Интеграция с AmoCRM.

#### `POST /call_center/submissions`
Прием заявок от Call Center.

### Модели данных

**LeadModel** - лид:
- `id` - UUID
- `borrower_phone` - телефон заемщика
- `source` - источник заявки
- `status` - статус лида
- `application_id` - ID заявки в partner API
- `elma_lead_id` - ID лида в ELMA

**Submission** - заявка:
- `borrower` - данные заемщика
- `loanParameters` - параметры кредита
- `source` - источник
- `utm` - UTM метки

### Интеграции

**ELMA CRM:**
- Создание лидов в ELMA
- Отправка данных заявки
- Получение статусов из ELMA
- Отправка промежутков времени для сделки

**AmoCRM:**
- Создание контактов
- Создание сделок
- Синхронизация статусов

**partner API:**
- Создание заявок в partner API
- Получение application_id

**solver API:**
- Расчет решений по заявкам

**Call Center:**
- Прием заявок от операторов
- Передача данных в Call Center

### Статусы лида

- `NEW` - новый лид
- `PROCESSING` - обрабатывается
- `CONVERTED` - конвертирован в заявку
- `REJECTED` - отклонен

### Конфигурация

Основные настройки:
- `elma_settings` - настройки ELMA
- `amocrm_settings` - настройки AmoCRM
- `b2b_settings` - настройки partner API
- `solver_settings` - настройки solver API

### Особенности

- Поддержка множественных источников заявок
- Обработка дубликатов по телефону
- Асинхронная обработка через Celery
- Интеграция с внешними CRM системами
- Отправка постбеков для уведомлений

## 5. consent - Сервис согласий

### Назначение
Управление согласиями клиентов на обработку персональных данных. Поддержка SMS согласий и подготовленных согласий.

### Технологии
- FastAPI
- Redis (для хранения временных данных)
- JWT аутентификация
- Интеграция с ELMA

### Основные функции
- Создание согласий через SMS
- Создание подготовленных согласий
- Получение данных клиентов по hash
- Отправка согласий в ELMA
- Управление ссылками на заявки

### API Endpoints

#### `POST /api/consent`
Создание нового согласия через SMS.

**Запрос:**
```json
{
  "mobile_phone": "+79991234567",
  "first_name": "Иван",
  "last_name": "Иванов",
  "passport_series": "1234",
  "passport_number": "567890"
}
```

**Ответ:**
```json
{
  "hash": "abc123"
}
```

#### `GET /api/client_data?hash=...`
Получение данных клиента по hash (для заполнения формы согласия).

#### `PUT /api/consent/{hash}`
Подтверждение согласия клиентом.

**Запрос:**
```json
{
  "agreement_signed_types": ["PERSONAL_DATA", "CREDIT_HISTORY"],
  "received_at": "2024-01-01T12:00:00Z",
  "expired_at": "2024-01-02T12:00:00Z",
  "signed_ip": "192.168.1.1"
}
```

#### `POST /api/prepared_consent`
Создание подготовленного согласия (с PDF файлом).

#### `POST /api/application_link`
Создание ссылки на заявку.

#### `GET /api/consents/disabled`
Получение списка отключенных телефонов.

### Модели данных

**Consent** - согласие:
- `first_name`, `last_name` - ФИО
- `mobile_phone` - телефон
- `passport_*` - паспортные данные
- `agreement_signed_types` - типы согласий
- `received_at`, `expired_at` - временные метки
- `signed_ip` - IP адрес подписания
- `source` - источник

**NewConsent** - запрос на создание согласия:
- `mobile_phone` - телефон
- `first_name`, `last_name` - ФИО
- `passport_*` - паспортные данные
- `callback_success`, `callback_error` - URL для колбэков

### Типы согласий

- `PERSONAL_DATA` - обработка персональных данных
- `CREDIT_HISTORY` - запрос кредитной истории
- `THIRD_PARTIES` - передача третьим лицам

### Интеграция

**ELMA CRM:**
- Отправка согласий в ELMA
- Получение подтверждений

**SMS Service:**
- Отправка SMS со ссылками на согласие

**partner API:**
- Получение данных для создания согласий
- Отправка результатов согласий

### Особенности

- Поддержка SMS согласий
- Поддержка подготовленных согласий (PDF)
- Временное хранение данных в Redis
- Интеграция с ELMA для отправки согласий
- Поддержка колбэков для уведомлений

## 6. recognition - Сервис распознавания документов

### Назначение
OCR (Optical Character Recognition) для документов: паспортов, ЕГРН и других документов. Интеграция с внешними провайдерами OCR.

### Технологии
- FastAPI
- Redis (для очередей задач)
- Внешние OCR провайдеры
- JWT аутентификация

### Основные функции
- Создание задач на распознавание
- Проверка статуса задач
- Получение результатов распознавания
- Поддержка различных форматов документов
- Автоматическое и ручное распознавание

### API Endpoints

#### `POST /api/tasks`
Создание задачи на распознавание.

**Запрос (multipart/form-data):**
- `files` - файлы для распознавания
- `rec_type_match` - JSON с типами распознавания для каждого файла
- `provider` - провайдер OCR (опционально)

**Ответ:**
```json
{
  "task_id": "uuid",
  "status": "PENDING"
}
```

#### `GET /api/tasks/{task_id}`
Проверка статуса задачи.

**Ответ:**
```json
{
  "task_id": "uuid",
  "status": "SUCCESS",
  "results": [
    {
      "file_name": "passport.jpg",
      "data": {
        "first_name": "Иван",
        "last_name": "Иванов",
        ...
      }
    }
  ]
}
```

#### `GET /api/tasks`
Список задач (с фильтрацией).

#### `GET /api/tasks/delete/old`
Удаление старых задач.

### Типы распознавания

- `0` - паспорт
- `1` - прочие документы
- `2` - ЕГРН

### Поддерживаемые форматы

- `image/bmp`
- `image/jpeg`
- `image/png`
- `image/tiff`
- `application/pdf`

### Статусы задач

- `PENDING` - ожидает обработки
- `PROCESSING` - обрабатывается
- `SUCCESS` - успешно распознано
- `FAILED` - ошибка распознавания
- `UNAVAILABLE` - провайдер недоступен

### Режимы работы

**Автоматический (AUTO):**
- Проверка каждую секунду
- Ожидание до 60 секунд

**Ручной (MANUAL):**
- Проверка каждые 10 секунд
- Ожидание до 15 минут

### Интеграция

**partner API:**
- Создание задач от partner API
- Получение результатов распознавания

**Внешние OCR провайдеры:**
- Отправка файлов на распознавание
- Получение результатов

### Особенности

- Поддержка множественных провайдеров OCR
- Асинхронная обработка задач
- Кэширование результатов
- Ограничение размера файлов (50MB)
- Поддержка пакетной обработки

## Общие принципы

### Аутентификация
Все сервисы используют централизованную аутентификацию через `auth` API. Токены передаются в заголовке `x-token` или `Authorization`.

### Логирование
Все сервисы используют структурированное логирование с контекстными фильтрами для трейсинга запросов.

### Обработка ошибок
Все сервисы возвращают структурированные ошибки и логируют их в Sentry.

### Конфигурация
Каждый сервис использует YAML конфигурационные файлы для настройки.

### Тестирование
Все сервисы имеют тесты (pytest для backend, jest/mocha для frontend).
