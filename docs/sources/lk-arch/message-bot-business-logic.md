## 1. Назначение

**Message-Bot** - Telegram бот для уведомлений и взаимодействия с пользователями через Telegram. Позволяет партнерам создавать заявки, просматривать их статусы и управлять данными через удобный интерфейс Telegram.

### Технологии

- aiogram - библиотека для работы с Telegram Bot API
- aiohttp - асинхронные HTTP запросы
- Redis - хранение токенов авторизации
- FSM (Finite State Machine) - управление состояниями диалогов

## 2. Модели данных

### Состояния диалогов (FSM)

#### AuthForm (Форма авторизации)

**AuthForm** - состояния для процесса авторизации.

| Состояние | Описание |
|-----------|----------|
| `phone` | Ввод номера телефона |
| `sms_code` | Ввод SMS кода |

#### NewAppForm (Форма создания заявки)

**NewAppForm** - состояния для создания новой заявки.

| Состояние | Описание |
|-----------|----------|
| `passport_image` | Загрузка фотографии паспорта |
| `registration_address` | Ввод адреса регистрации |
| `work_type` | Выбор трудового статуса |
| `phone_to_send_consent` | Ввод телефона для отправки согласия |
| `product_type` | Выбор типа продукта |
| `credit_amount` | Ввод суммы кредита |
| `comfort_month_payment` | Ввод комфортной суммы платежа |
| `pledge_address` | Ввод адреса объекта залога |
| `pledge_type` | Выбор типа объекта залога |
| `floor` | Ввод этажа |
| `number_of_storeys` | Ввод этажности |
| `area` | Ввод площади |
| `rooms` | Ввод количества комнат |
| `cadastral_number` | Ввод кадастрового номера |

### Хранение данных

#### Redis Storage

**Структура ключей:**

- `bot:{chat_id}` - токен авторизации пользователя
  - Значение: JWT токен
  - TTL: 3600 секунд (1 час)

**Использование:**

- Хранение токенов авторизации
- Проверка авторизации пользователя
- Управление сессиями

## 3. Бизнес-логика

### Авторизация

#### Команда `/auth`

**Процесс:**

1. **Проверка авторизации:**
   - Проверка наличия токена в Redis: `bot:{chat_id}`
   - Если токен существует → сообщение "Вы уже авторизованы!"

2. **Начало процесса:**
   - Установка состояния `AuthForm.phone`
   - Запрос номера телефона

#### Обработка номера телефона (`process_name`)

**Процесс:**

1. **Получение SMS токена:**
   - Вызов `b2b.get_sms_token(cell_phone)`
   - POST запрос к partner API: `/api/auth/sms_token`
   - Получение `sms_token`

2. **Обработка ошибки:**
   - Если токен не получен → завершение состояния
   - Сообщение: "Неверный номер телефона."

3. **Сохранение данных:**
   - Сохранение `phone` и `sms_token` в состоянии
   - Переход к состоянию `AuthForm.sms_code`
   - Запрос SMS кода

#### Обработка SMS кода (`process_age`)

**Процесс:**

1. **Валидация кода:**
   - Проверка, что код состоит только из цифр
   - Если нет → сообщение "СМС-код должен состоять только из цифр"

2. **Верификация кода:**
   - Вызов `b2b.verify_sms_code(sms_token, sms_code)`
   - POST запрос к partner API: `/api/auth/verify_sms`
   - Получение данных пользователя и токена

3. **Обработка ошибки:**
   - Если код неверен → сообщение "Неверный СМС-код. Введите код еще раз."
   - Повторный запрос кода

4. **Сохранение токена:**
   - Сохранение токена в Redis: `bot:{chat_id} = auth_token`
   - TTL: 3600 секунд

5. **Приветствие:**
   - Формирование ФИО пользователя
   - Сообщение: "Добро пожаловать, {ФИО}"

6. **Завершение:**
   - Завершение состояния FSM

### Создание заявки

#### Команда `/new`

**Процесс:**

1. **Проверка авторизации:**
   - Проверка токена в Redis
   - Если нет → сообщение "Вы не авторизованы!"

2. **Создание заявки:**
   - Вызов `b2b.create_new_application(auth_token)`
   - POST запрос к partner API: `/api/applications`
   - Получение `application_id`, `borrower_id`, `product_id`

3. **Обработка ошибки:**
   - Если заявка не создана → сообщение об ошибке

4. **Сохранение данных:**
   - Сохранение ID в состоянии FSM
   - Установка состояния `NewAppForm.passport_image`
   - Инструкции по заполнению заявки

#### Загрузка паспорта (`process_passport_image`)

**Процесс:**

1. **Проверка фотографии:**
   - Проверка наличия фотографии в сообщении
   - Если нет → сообщение "Вы не вложили фотографию"

2. **Загрузка файла:**
   - Получение файла через `message.photo[-1].get_file()`
   - Скачивание в `BytesIO`

3. **Отправка в partner API:**
   - Формирование `FormData`:
     - `document_type: "passport"`
     - `files: photo_data`
   - POST запрос: `/api/borrowers/{borrower_id}/recognize/passport`

4. **Обработка результата:**
   - Если успешно → переход к следующему шагу
   - Если ошибка → сообщение об ошибке

5. **Следующий шаг:**
   - Переход к состоянию `NewAppForm.registration_address`
   - Запрос адреса регистрации

#### Ввод адреса регистрации (`process_passport_image`)

**Процесс:**

1. **Сохранение адреса:**
   - Сохранение `registration_address` в состоянии

2. **Следующий шаг:**
   - Переход к состоянию `NewAppForm.work_type`
   - Отображение клавиатуры с вариантами:
     - "Наемный работник"
     - "ИП"
     - "Самозанятый"
     - "Владелец бизнеса, доля < 25%"
     - "Владелец бизнеса, доля > 25%"

#### Выбор трудового статуса (`process_gender`)

**Процесс:**

1. **Валидация выбора:**
   - Проверка, что выбран один из вариантов
   - Если нет → сообщение "Неверный трудовой статус. Выберите трудовой статус из списка"

2. **Маппинг значений:**
   - Маппинг текста в код:
     - "Наемный работник" → "employee"
     - "ИП" → "individual"
     - "Самозанятый" → "self_employed"
     - "Владелец бизнеса, доля < 25%" → "business_owner_less_than_25_share"
     - "Владелец бизнеса, доля > 25%" → "business_owner_more_than_25_share"

3. **Следующий шаг:**
   - Сохранение `work_type` в состоянии
   - Переход к состоянию `NewAppForm.phone_to_send_consent`
   - Запрос номера телефона для согласия

#### Ввод телефона для согласия (`process_consent_phone`)

**Процесс:**

1. **Валидация телефона:**
   - Проверка, что телефон состоит только из цифр
   - Если нет → сообщение "Номер телефона должен состоять только из цифр"

2. **Обновление заемщика:**
   - Вызов `b2b.update_borrower(auth_token, borrower_id, {...})`
   - PUT запрос: `/api/borrowers/{borrower_id}`
   - Данные: `employment_relation_type`, `registration_address`

3. **Отправка согласия:**
   - Вызов `b2b.send_consent_for_borrower(auth_token, borrower_id, phone)`
   - POST запрос: `/api/borrowers/{borrower_id}/consent/by/sms`

4. **Следующий шаг:**
   - Переход к состоянию `NewAppForm.product_type`
   - Отображение клавиатуры с продуктами:
     - "Залог"
     - "Ипотека"
     - "Рефинансирование"

#### Выбор типа продукта (`process_product_type`)

**Процесс:**

1. **Валидация выбора:**
   - Проверка, что выбран один из вариантов
   - Если нет → сообщение "Выберите продукт из списка"

2. **Маппинг значений:**
   - "Залог" → "CASHONBAIL"
   - "Ипотека" → "MORTGAGE"
   - "Рефинансирование" → "REFINANCING"

3. **Следующий шаг:**
   - Сохранение `product_type` в состоянии
   - Переход к состоянию `NewAppForm.credit_amount`
   - Запрос суммы кредита

#### Ввод суммы кредита (`process_credit_amount`)

**Процесс:**

1. **Валидация:**
   - Парсинг в `float`
   - Если ошибка → сообщение "Только числовое значение!"

2. **Следующий шаг:**
   - Сохранение `credit_amount` в состоянии
   - Переход к состоянию `NewAppForm.comfort_month_payment`
   - Запрос комфортной суммы платежа

#### Ввод комфортной суммы платежа (`process_comfort_month_payment`)

2. **Следующий шаг:**

#### Ввод адреса объекта залога (`process_pledge_address`)

   - Отображение клавиатуры:
     - "Квартира"
     - "Апартаменты"
     - "Коммерческий"

#### Выбор типа объекта залога (`process_pledge_type`)

**Процесс:**

1. **Маппинг значений:**
   - "Квартира" → "FLAT"
   - "Апартаменты" → "APARTMENT"
   - "Коммерческий" → "COMMERCIAL"

2. **Следующий шаг:**
   - Сохранение `pledge_type` в состоянии
   - Переход к состоянию `NewAppForm.floor`

#### Ввод этажа (`process_floor`)

### Просмотр заявок

#### Команда `/lastfive`

**Процесс:**

### Отмена операций

#### Команда `/cancel`

**Процесс:**

1. **Проверка состояния:**

   - Вызов `state.finish()`

## 4. Команды бота

### Основные команды

#### `/start`

**Назначение:** Приветствие и список команд.

**Ответ:**
```
Бот кабинета B2B банка БЖФ
Основные команды бота
/auth - авторизация партнера
/new - создать новую заявку
/lastfive - показать последние 5 заявок
```

**Назначение:** Авторизация партнера.

**Процесс:**
- Запрос номера телефона

- Сохранение токена в Redis

**Назначение:** Создание новой заявки.

**Процесс:**
- Создание заявки в partner API

**Назначение:** Отмена текущей операции.

- Завершение текущего состояния FSM

## 5. Интеграции

### Partner API

**Endpoints:**

1. **Авторизация:**
   - `POST /api/auth/sms_token` - получение SMS токена
   - `POST /api/auth/verify_sms` - верификация SMS кода

2. **Заявки:**
   - `POST /api/applications` - создание заявки
   - `GET /api/applications` - список заявок
   - `GET /api/applications/{id}` - получение заявки
   - `POST /api/applications/{id}/prior_approval` - отправка в ELMA

3. **Заемщики:**
   - `POST /api/borrowers/{id}/recognize/passport` - распознавание паспорта
   - `PUT /api/borrowers/{id}` - обновление заемщика
   - `POST /api/borrowers/{id}/consent/by/sms` - отправка согласия

4. **Продукты:**
   - `POST /api/products` - обновление продукта

**Аутентификация:**

- JWT токен в заголовке `Authorization`
- Токен получается при авторизации через SMS
- Хранится в Redis с TTL 1 час

### Redis

**Использование:**

- Хранение токенов авторизации: `bot:{chat_id}`
- TTL: 3600 секунд
- Проверка авторизации перед каждым действием

## 6. Особенности архитектуры

### FSM (Finite State Machine)

**Управление состояниями:**

- Использование `aiogram.dispatcher.fsm_storage.memory.MemoryStorage`
- Состояния хранятся в памяти
- Автоматическое управление переходами между состояниями

**Преимущества:**

- Структурированный диалог
- Валидация на каждом шаге
- Возможность отмены в любой момент

### Inline клавиатуры

**Использование:**

- Для выбора вариантов (трудовой статус, тип продукта, тип объекта)
- Для навигации (просмотр заявок, возврат к списку)
- Callback data для обработки действий

**Формат:**

- `application:{id}:{action}` - для заявок
- `action` может быть: `view`, `list`

### Форматирование сообщений

**Использование:**

- `aiogram.utils.markdown` для форматирования
- HTML разметка для выделения текста
- Эмодзи для улучшения UX

**Примеры:**

- `md.hbold()` - жирный текст
- `md.hitalic()` - курсив
- `md.quote_html()` - цитата

### Обработка ошибок

**Валидация:**

- Проверка типов данных (числа, текст)
- Проверка выбора из списка
- Проверка наличия файлов

**Обработка:**

- Информативные сообщения об ошибках
- Возможность повторного ввода
- Graceful degradation при ошибках API

### Безопасность

**Авторизация:**

- Проверка токена перед каждым действием
- Хранение токенов в Redis с ограниченным TTL
- Автоматический выход при истечении токена

**Валидация данных:**

- Проверка всех входных данных
- Санитизация данных перед отправкой в API
