# Архитектурный обзор проекта Банка жилищного финансирования

## Общее описание

Проект Банка жилищного финансирования (BGF) представляет собой микросервисную банковскую платформу для работы с кредитными продуктами, ипотекой, партнерами и обработки заявок. Система построена на принципах микросервисной архитектуры с разделением ответственности между сервисами.

## Технологический стек

### Backend
- **Язык программирования**: Python 3.11/3.12
- **Веб-фреймворк**: FastAPI
- **База данных**: PostgreSQL (12-13)
- **Кэширование и очереди**: Redis 5.x
- **Очереди сообщений**: RabbitMQ 3.8.x
- **Асинхронные задачи**: Celery 5.4+
- **ORM**: SQLAlchemy 2.0 (async)
- **Миграции**: Alembic 1.13+
- **Валидация данных**: Pydantic 2.x

### Frontend
- **Фреймворк**: Vue.js 3.4
- **Сборщик**: Vue CLI / Vite
- **Роутинг**: Vue Router 4
- **Управление состоянием**: Vuex / Pinia
- **HTTP клиент**: Axios
- **Node.js**: 18/20

### Инфраструктура
- **Контейнеризация**: Docker
- **Оркестрация**: Docker Compose, Kubernetes
- **Веб-сервер**: Nginx
- **Мониторинг**: Sentry (sentry-sdk)

## Микросервисы

### 1. **auth** - Сервис аутентификации
**Назначение**: Централизованная аутентификация и авторизация для всех сервисов

**Технологии**:
- FastAPI
- JWT токены
- Redis (для хранения сессий)

**Основные функции**:
- Выдача токенов доступа
- Валидация токенов
- Управление сессиями

**Порт**: 9090

---

### 2. **solver** - Сервис расчета кредитных решений
**Назначение**: Расчет кредитных предложений, LTV (Loan-to-Value), максимальных сумм кредита

**Технологии**:
- FastAPI
- PostgreSQL
- Конфигурационные JSON файлы для продуктов и условий

**Основные функции**:
- Расчет кредитных предложений
- Определение LTV в зависимости от региона, кредитной истории, типа недвижимости
- Калькулятор для партнеров (CIAN)
- Принятие решений по заявкам

**Порт**: 9090

**Особенности**:
- Использует сложную систему условий для расчета LTV
- Поддерживает множество кредитных продуктов
- Динамическая конфигурация через JSON файлы

---

### 3. **partner** - API для партнеров
**Назначение**: Основной API для работы партнеров с заявками, клиентами, документами

**Технологии**:
- FastAPI
- PostgreSQL (Alembic миграции)
- Redis
- RabbitMQ (для уведомлений)
- WebSocket (для real-time уведомлений)
- Celery (для фоновых задач)

**Основные функции**:
- Управление заявками (applications)
- Работа с клиентами (borrowers)
- Загрузка и обработка документов
- Интеграция с recognition API для OCR
- Интеграция с consent API для согласий
- Уведомления через WebSocket
- Финансовые операции
- Управление продуктами

**Порт**: 9090

**База данных**: `partner_db`

---

### 4. **reception** - Сервис приема заявок
**Назначение**: Прием и обработка заявок от различных источников

**Технологии**:
- FastAPI
- PostgreSQL (async)
- Redis
- RabbitMQ
- Celery

**Основные функции**:
- Прием заявок (submissions)
- Интеграция с AmoCRM
- Интеграция с call center
- Обработка email-лидов
- Интеграция с ELMA
- Административные функции

**Порт**: 9090

**База данных**: `reception_db`

---

### 5. **consent** - Сервис согласий
**Назначение**: Управление согласиями клиентов на обработку персональных данных

**Технологии**:
- FastAPI
- JWT аутентификация

**Основные функции**:
- Создание согласий
- Отправка подготовленных согласий
- Получение данных клиентов
- Управление ссылками на заявки

**Порт**: 9090

---

### 6. **recognition** - Сервис распознавания документов
**Назначение**: OCR (Optical Character Recognition) для документов

**Технологии**:
- FastAPI
- Redis (для очередей задач)
- Внешние провайдеры OCR

**Основные функции**:
- Создание задач на распознавание
- Проверка статуса задач
- Поддержка различных форматов (BMP, JPEG, PNG, TIFF, PDF)
- Автоматическое и ручное распознавание

**Порт**: 9090

---

### 7. **findsign** - Сервис поиска подписи
**Назначение**: Поиск и валидация подписей в документах

**Технологии**:
- FastAPI
- JWT аутентификация

**Основные функции**:
- Поиск подписи в распознанных документах
- Валидация наличия подписи

**Порт**: 9090

---

### 8. **extpartner** - API для внешних партнеров
**Назначение**: API для интеграции с внешними партнерами

**Технологии**:
- FastAPI
- Celery
- OpenAPI спецификация

**Основные функции**:
- Интеграция с внешними партнерами
- Call center интеграция
- Управление заявками от внешних источников

**Порт**: 9090

---

### 9. **productolog** - Сервис продуктов
**Назначение**: Управление кредитными продуктами и их конфигурацией

**Технологии**:
- FastAPI
- PostgreSQL (async)
- Alembic миграции

**Основные функции**:
- Управление кредитными продуктами
- Конфигурация условий продуктов
- Миграции схемы БД

**Порт**: 9090

**База данных**: отдельная БД для продуктов

---

### 10. **cian** - Интеграция с CIAN
**Назначение**: Интеграция с маркетплейсом CIAN для работы с заявками

**Технологии**:
- Celery (асинхронные задачи)
- FastAPI (для некоторых endpoints)
- Elasticsearch (для хранения данных)
- Redis (для кэширования)

**Основные функции**:
- Синхронизация заявок с CIAN
- Отправка решений в CIAN
- Работа с marketplace API CIAN
- Хранение документов CIAN

**Особенности**:
- Работает как Celery worker
- Интегрируется с solver_api и reception_api
- Использует OAuth2 для аутентификации в CIAN

---

### 11. **message-bot** - Telegram бот
**Назначение**: Telegram бот для уведомлений и взаимодействия

**Технологии**:
- python-telegram-bot
- HTTP клиенты для интеграции с API

**Основные функции**:
- Обработка сообщений в Telegram
- Интеграция с backend API
- Уведомления пользователей

---

### 12. **reception-data** - ETL для данных reception
**Назначение**: Обработка и трансформация данных для reception

**Технологии**:
- SQLAlchemy 2.0 (async)
- PostgreSQL
- Alembic

**Основные функции**:
- ETL процессы для данных reception
- Миграции данных

## Взаимодействие сервисов

### Синхронное взаимодействие (HTTP/REST)

```
Frontend → auth (аутентификация)
Frontend → partner (основной API)
partner → auth (валидация токенов)
partner → solver (расчет кредитных предложений)
partner → recognition (OCR документов)
partner → consent (согласия)
cian → solver (расчет для CIAN)
cian → reception (отправка заявок)
reception → solver (расчет решений)
```

### Асинхронное взаимодействие (RabbitMQ)

```
partner → RabbitMQ → WebSocket уведомления
reception → RabbitMQ → фоновые задачи
extpartner → RabbitMQ → Celery задачи
```

### Очереди задач (Celery)

- **cian**: обработка заявок от CIAN
- **reception**: обработка email-лидов, интеграция с AmoCRM
- **extpartner**: фоновые задачи для внешних партнеров
- **partner**: фоновые задачи обработки документов

## Базы данных

### PostgreSQL инстансы

1. **partner_db** - данные партнеров, заявок, клиентов
2. **reception_db** - данные заявок reception
3. **solver_db** - данные для расчетов (если используется)
4. **productolog_db** - данные продуктов
5. **reception_data_db** - ETL данные

Каждый сервис может иметь свою базу данных или использовать общую, в зависимости от конфигурации.

## Безопасность

### Аутентификация
- Централизованная через `auth` сервис
- JWT токены для межсервисного взаимодействия
- Базовая схема аутентификации для некоторых сервисов

### Авторизация
- Проверка прав доступа на уровне API
- Роли пользователей (admin, partner, etc.)

### Защита API
- CORS настройки для фронтенд приложений
- Валидация токенов через заголовки
- Ограничение размера контента

## Мониторинг и логирование

- **Sentry**: отслеживание ошибок и исключений
- **Логирование**: структурированное логирование через Python logging
- **Контекстные фильтры**: для трейсинга запросов

## Деплой

### Docker
- Каждый сервис имеет свой Dockerfile
- Docker Compose для локальной разработки и тестирования
- Kubernetes для продакшн окружения

### Порты
- Все API сервисы используют порт **9090** (внутри контейнеров)
- Nginx для проксирования и балансировки нагрузки

## Принципы архитектуры

1. **Микросервисная архитектура**: каждый сервис отвечает за свою область
2. **Асинхронность**: использование async/await и Celery для тяжелых операций
3. **Масштабируемость**: горизонтальное масштабирование через Docker/Kubernetes
4. **Разделение ответственности**: четкое разделение между сервисами
5. **Переиспользование кода**: общая библиотека bgf-utils
6. **Конфигурируемость**: настройка через YAML/JSON файлы
