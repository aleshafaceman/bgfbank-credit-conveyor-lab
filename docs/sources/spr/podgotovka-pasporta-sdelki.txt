Экран общий для финальных стадий (заключение сделки, подготовка КОД, подготовка паспорта сделки).Фаза 1. Инициация. Проверка на активные процессы; при наличии запущенного — ознакомление и закрытие; иначе — синхронизация контекста.Фаза 2. Выбор режима и даты сделки. Шлюз «Авто / Ручная». Авто → определение по региону (Москва → график ОЗС; регион → календарь) и шлюз «Предварительная»: да → подтверждение даты (B2B) с завершением; нет → смена статуса B2B и подготовка информации. Ручная → формирование уведомления по ДУ.Фаза 3. Подготовка информации по сделке (ключевой шаг). Подготовить информацию; ветки: поставить в график, отказ клиента, вернуться на этап (повторное рассмотрение).Фаза 4. Формирование паспорта и КОД. Блок «Покупатели» → график сделок → кредитный договор и договор страхования → обратная синхронизация (подготовка КОД) → списки ДУ и физлиц → обработка участников → счётчик → точная идентификация клиентов.Фаза 5. Идентификация и завершение. Проверка завершения идентификации → проверка копий ДУ, обогащение отчёта → подготовка КОД → завершение.Проблемы:Логика назначения даты сделки жёстко завязана на конкретный регион (Москва/не Москва) прямо в процессе — при выходе в новый регион или изменении правил записи придётся менять сам процесс, а не настройку.
