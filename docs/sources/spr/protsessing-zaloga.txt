Процессинг залогаКраткая сводкаОтветственный Чернов Георгий Григорьевич Статус описанияУТВЕРЖДЕН НА СОГЛАСОВАНИИ НЕ УТВЕРЖДЕНКраткое описаниеКонтекстЗадействованные системы: ELMAВнешние интеграции: внутренний механизм проверки СБРоли: инициатор, процессор, сотрудник продаж / процессор B2B, служба безопасностиВизуальная схема/Пошаговое описаниеЭтап выполняется в трёх зонах: инициатор, процессор и сотрудник продаж / процессор B2B. Ключевая особенность — контур доработки по проверке СБ.Фаза 1. Инициация (инициатор). Определение ответственного, смена статуса, распределение прав, установка хэша для проверки СБ, формирование списка ДУ и уведомления по ДУ, синхронизации. Шлюз «Нужна проверка» → рассмотрение заявки СБ.Фаза 2. Обработка процессором. Обработка результатов оценки залога, отправка на оценку, экспресс-оценка, расчёт приоритета; при необходимости — контур доработки.Фаза 3. Отправка на андеррайтинг. Создание/обновление продавцов, синхронизация и отправка на андеррайтинг, приоритет → шлюз «Нужна доработка (СБ)»: нет — андеррайтинг залога; да — доработка по СБ.Фаза 4. Доработка (процессор / B2B). Оповещение о доработке СБ, отправка на доработку, доработка информации по залогу, оспаривание, повторный процессинг; отдельная ветка — отказ клиента.Проблемы:Возврат на проверку СБ зациклен без ограничения — а именно проверка СБ по практике самая долгая по времени, и здесь как раз нет тайм-аута или эскалации, если она подвисла.
