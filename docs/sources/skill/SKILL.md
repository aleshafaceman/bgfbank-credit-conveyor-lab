# Работа банка БЖФ

АО «Банк БЖФ» (бренд БЖФ Банк, лицензия 3138) выдаёт кредиты под залог жилья (покупка, нецелевой залог, рефинансирование; отдельно — ЮЛ и опция «Зелёный коридор»). Оркестратор **сегодня — ELMA**. ЛК `cabinet` — два входа одного SPA: партнёр (`https://lk.bgfbank.ru`, препрод `https://pp.bgfbank.ru/`) и менеджер (`/manager`). Это канал брокера/сейла и проекция статусов, не АРМ АНД/СБ/ОЗС.

Перед ответом или кодом зафиксируй контур: **AS-IS (ELMA жива)**, **sidecar `deal-ops` (после КОД, ELMA ещё ведёт заявку)** или **TO-BE (Conveyor)**. Не смешивай их как будто все уже в проде.

## Инструкции

1. Прочитай этот файл целиком. Детали — по ссылкам ниже, не выдумывай чужой ипотечный конвейер.
2. Сущности банка: **лид** (короткая заявка) и **заявка/сделка** (Sale). Это разные объекты ELMA, связанные конвертацией.
3. В заявке всегда два предмета рассмотрения: **человек** (АНД) и **объект** (АПЗ). Паспорт сделки открывается только когда оба одобрены.
4. После «КОД сформирован» офис **не** продолжает работу в ELMA: снимок уходит в `deal-ops`. Клиент сидит у ОЗС, второго окна ОПЕРУ нет.
5. Статусы партнёрского ЛК (`ApplicationStatus`) — **схлопывание** 53 кодов ELMA. Оператор банка видит точную стадию и задачу.
6. Канон в репо: `docs/architecture/to-be-process.md`, `to-be-overview.md`, `elma-strangler.md`, `to-be-integrations.md`, **`account-opening-strangler.md`**. Enum стадий: `Elma3StageStatusEnum` в `bgf-backend/bgf-utils/bgf_utils/rest/enums/elma.py`. При расхождении верь коду и этим docs, не памяти.
7. Не копируй ПДн из выгрузок ELMA (ФИО, телефоны, адреса, кадастр, паспорта) в скиллы, тикеты и примеры кода.

## Жёсткие правила

| Не путать | Это | Не это |
|-----------|-----|--------|
| Loginom | СПР банка: `preScore`, `getDecision`, ПДН, ФССП | Solver |
| Solver | пакеты / LTV / ставка на входе в ЛК и форме | скоринг АНД |
| ЦФТ | АБС: клиент, КД, счёт РКО, аккредитив, закладная | CRM / ELMA |
| МО | цена объекта (lookup / express / отчёт) | решение по клиенту |
| SmartDeal `signing_channel` | электронное **подписание КОД** (УКЭП, пакет) | Росреестр (`StartERegistration`) и не выдача |
| ЛК `cabinet` | партнёр `/` и менеджер `/manager`, auth через `elma_id` | АРМ АНД/СБ/ОЗС и не клиентская форма ЕСИА |
| Госключ | УКЭП клиента в приложении Госуслуг, презентация партнёрам 09.2026 | SmartDeal-адаптер и не логин ЕСИА в кабинет |
| «Зелёный коридор» | продуктовая опция сложной КИ | отдельный `CreditPurposeEnum` |
| ЮЛ-заёмщик | кредит организации под залог | ЮЛ-партнёр (`new_juridical_person` в регистрации ЛК) |
| `deal-ops` | sidecar после КОД: снимок, ОЗС, exception ОПЕРУ, счёт | новая BPMS и не `cabinet` |
| ОПЕРУ | очередь `error` автопроверок счёта | второе окно идентификации |
| Conveyor | целевой оркестратор TO-BE | текущий прод |

Другие запреты:

- Не предлагай Camunda / ELMA4 / Directum как замену. Решение TO-BE: доменный сервис `conveyor` в стеке ЛК.
- Не вешай заёмщика сайта и роли банка на `partner` auth.
- Не вызывай Loginom / ЦФТ / SmartDeal / проверки ФНС-МВД из UI. Только оркестратор → адаптер → outbox.
- Не добавляй в ELMA проверки счёта, шаблон заявления, телефон, ручное открытие счёта. Из плана MPP в ELMA — только **экспорт снимка** и **callback статуса**.
- Не парси публичные HTML ФНС / МВД / Федресурс / ФТС.
- Не переподписывай СОПД «датой визита». Нет отдельного согласия на счёт. Добор **полной** формы — только если первое недостаточно.
- Не зови ЕСИА повторно за столом. Сделка — очная идентификация; `esia_consent` / `verified_via` приходят **в снимке**.
- Не смешивай подписание КОД, заявление на **открытие счёта** и заявление на **ДБО** (+ приложение 1).
- Не считай «Залог одобрен» в истории лидом: это стадия заявки (ELMA 23), барьер к паспорту вместе с «Клиент одобрен» (ELMA 5).
- Не клади в АРМ `deal-ops` v1 календарь паспорта сделки, процессинг КОД (ОПС) и обращение в Росреестр.
- Не подставляй КВ и ставки «от X%» из памяти: бери [partner-offer.md](partner-offer.md) (презентация 01.09.2026) и помечай акцию по сроку. Внутренний рефин — без КВ.
- Не добавляй четвёртый `CreditPurposeEnum` под «коридор», «купи ставку» или ЮЛ — в коде три цели.
- Не подменяй `signing_channel=smartdeal` Госключом, пока нет команды в интеграциях.
- В UI не искажай логотип, не заливай зелёным фон/знак, шрифт бренда — Roboto. Токены: [brand.md](brand.md).
- Не путай **клиентскую** форму ЕСИА (`esia-screens.md`) с шагом 1 быстрой заявки `cabinet`. Макет кабинета: [cabinet.md](cabinet.md).
- «Третий экран» в сырых постановках ≠ шаг добавления созаёмщика: на быстрой заявке созаёмщик добавляется **на шаге 1**. Шаг 3 — «Документы».
- CTA шага 1 — **«Получить пре-оффер»**, не «Далее». Поля ИНН в AS-IS кабинета нет (проверка pp 15.09.2026).
- «Заполнить вручную» (`by_uploaded_consent`, бумажное СОПД) — **только менеджер**. Партнёр видит Госуслуги и анкету по SMS.
- В ELMA из ЛК ходи только **PublicAPI** (`LeadCreator`, `CabinetB2B`). Корневой `EntityService` не дыра, чтобы дописать ИНН/файлы в «Потенциального клиента». Канон: [elma-webapi.md](elma-webapi.md).

## Как отвечать про процесс

Короткий скелет AS-IS (целевой TO-BE — те же этапы, другой движок; после КОД возможен sidecar):

```
канал → лид → дубль → прескоринг → оценка → идентификация ЦФТ
  → конвертация в заявку
  → сбор документов → заполнение → процессинг → СБ → АНД/АПЗ
  → паспорт сделки → КОД сформирован
  → deal-ops: снимок → идентификация ОЗС → ДУ → счёт ЦФТ
       → автопроверки → заявление РКО → подписание КОД → ДБО
  → выдача ОБУКО на известный счёт → регистрация / аккредитив / закладная → архив
```

Возвраты — норма, не сбой: отказ банка, доработка продаж/процессинга, повтор АНД, второй участник (созаёмщик), ДУ до сделки или до выдачи, возврат КОД на ОПС, отказ клиента от подписи.

Если пользователь принёс выгрузку ELMA (.xlsx карточки):

- игнорируй хром UI («Обновить», «15select», пагинация);
- задачи часто **веер** на очередь — бизнес-смысл в названии процесса, не в числе строк;
- хронология в гридах обычно **новые сверху**;
- листы лида и заявки читай как два объекта, конвертацию ищи в «История запросов».

Шаблон ответа:

1. Контур (AS-IS / deal-ops sidecar / TO-BE).
2. Объект (лид или заявка) и стадия.
3. Кто делает (роль) и какая система считает.
4. Что открывает следующий шаг (событие, не кнопка UI).
