# Получение сведений об объекте залога

Справка по источникам данных об объекте залога: что откуда берётся, чего нет ни у одной системы и что нужно решить до реализации.

Дата: 22.09.2026. Статус: **справочная записка, не решение**. Изменения в код и макеты по этому документу не вносились.

## 1. Зачем документ

В лабораторном макете ([`form-pledge/`](../../form-pledge/), экран «Карточка ЕГРН») сведения об объекте показываются одной карточкой: адрес, тип, площадь, этаж, кадастр, доля, правообладатель, обременения. Карточка заполняется мгновенно по введённому кадастровому номеру.

Такого канала не существует. Этот документ фиксирует, какие источники есть в реальности, что именно каждый отдаёт и где проходит граница данных.

## 2. Три группы данных и три разных источника

Ключ к теме: сведения об объекте делятся на группы, и у каждой **свой** источник. Путаница возникает, когда их считают одним набором.

| Группа | Состав |
|---|---|
| Адрес и характеристики | адрес, тип объекта, площадь, этаж, этажность, число комнат, год постройки, материал стен |
| Кадастровый номер | кадастр квартиры (не здания) |
| Юридические факты | правообладатель, доля, обременения |

**Юридические факты не даёт ни один из «сервисных» источников.** Это принципиально: оценщик оценивает, реестр подтверждает право.

## 3. Сводная таблица: кто что отдаёт

| Сведение | Источник | Тип получения | Статус контракта |
|---|---|---|---|
| Адрес (нормализованный) | Мобильный оценщик, Gate / Lookup | HTTP-запрос | Есть (OpenAPI) |
| Адрес (подсказки) | DaData | HTTP-запрос | Есть |
| Площадь | МО (`flat.area`), DaData (`area`) | HTTP-запрос | Есть |
| Этаж, комнаты | МО (`flat.floor`, `flat.rooms`) | HTTP-запрос | Есть |
| Этажность | МО (`bld.maxFloor`) | HTTP-запрос | Есть |
| Тип дома, материал стен | МО (`bld.bldType`, `bld.wallMaterial`) | HTTP-запрос | Есть |
| Год постройки | МО (`bld.bldYear`) | HTTP-запрос | Есть, может быть `null` |
| **Кадастр квартиры** | МО (`flat.cadNum`) | HTTP-запрос | Есть, **с оговоркой** (см. §4.3) |
| Кадастр здания | МО (`bld.cadNum`) | HTTP-запрос | Есть. Это **не** кадастр квартиры |
| Цена (экспресс) | МО (`stats.price`) | HTTP-запрос | Есть |
| Цена (официальная оценка) | МО, отчёт оценщика | Задача + отчёт | Есть, стадии P1/MFMS не разобраны |
| **Правообладатель, доля, обременения** | **ЕГРН** | **выписка: файл + OCR (AS-IS)** | **Живого контракта нет** |
| Кадастр (ручной ввод) | клиент / менеджер | ввод в форме | — |

## 4. Источники подробно

### 4.1. Мобильный оценщик — основной поставщик характеристик

Два разных API:

- **Gate / Lookup** — `https://api.ocenka.mobi/v1/appraise/flat?address=...`, справочник. Stateless, задача в кабинете МО **не создаётся** (`mobile-appraiser-integration.md`, §5.4). Вызывается при смене адреса: `apply_changes_to_product()` → `ExpressAppraiser.apply()`.
- **Express** — `express.ocenka.mobi`, создаёт задачу.

Маппинг ответа Lookup в поля заявки (`mobile-appraiser-integration.md`, §5.2):

| Поле продукта | Путь в ответе МО |
|---|---|
| `floor` | `flat.floor` |
| `rooms` | `flat.rooms` |
| `area` | `flat.area` |
| `number_of_storeys` | `bld.maxFloor` |
| `construction_year` | `bld.bldYear` |
| `cadastral_or_conditional_number` | `flat.cadNum` |
| `premise_material` | `bld.bldType` (маппинг в ELMA-enum) |
| `building_price` | `stats.price` — **только для партнёра** |
| `appraisal_building_price` | `stats.price` — **только для партнёра** |

Что ещё в ответе (`get_appraise_flat.md`): `address` — нормализованный адрес; `bld` — координаты, этажность, год, материал стен, `bldType`, `cadNum` **ОКС**, фото, станции; `bld.quality` — точность геокода (`success` дом / `warning` улица / `danger` НП); `stats.priceRange` — квартильный диапазон.

Обратный метод: `GET https://api.ocenka.mobi/v1/cad/search?cadNum=...` — по кадастру находит адрес. Применяется в `bring_to_underwriting`, **если адреса нет, а кадастр есть**.

### 4.2. DaData — адрес и площадь, не оценка

Подсказки адреса и `building_price` (цена за м² × площадь). В интеграциях зафиксировано прямо:

> «DaData — подсказки адреса, это не оценка.»
> — `lk-external-integrations.html`, стр. 382

В кабинете на первом экране залога из ответа берётся **только площадь**; `building_price` из DaData там не сохраняется (`mobile-appraiser-integration.md`, §8).

### 4.3. Оговорка по кадастру квартиры — важная

`flat.cadNum` приходит **не всегда**. По спецификации Gate (`get_appraise_flat.md`):

- в Gate **нет** `fiasId` и `cadNum` — они есть у `/search/bld` и `/find/flat`;
- блок `flat` может отсутствовать, если не передан `forceFlat` (по умолчанию поиск квартиры в Росреестре идёт только когда нет `area`);
- в схеме swagger от 2026-01-28 и в живом ответе без `forceFlat` блока `flat` может не быть — в документе стоит explicit-запрет «не выдумывать».

Практический вывод: **кадастр здания** (`bld.cadNum`) доступен надёжнее, чем **кадастр квартиры** (`flat.cadNum`). Для залога нужен второй.

### 4.4. ЕГРН — единственный источник права и обременений

Ни МО, ни DaData не отдают правообладателя, долю и обременения. Это данные Росреестра.

**В AS-IS это не запрос, а документ:**

> «`recognition` — Basis OCR (`api.doc.basis.center`) — Паспорт, ЕГРН, 2-НДФЛ. **ЕГРН в AS-IS — файл + OCR, не СМЭВ**»
> — `lk-external-integrations.html`, стр. 578

И в базе знаний, дважды, включая прямой запрет:

> «ЕГРН AS-IS = файл+OCR, не СМЭВ»
> «Не собирать: … payload СМЭВ ЕГРН (AS-IS — файл+OCR)»
> — `docs/_LK_KNOWLEDGE_BASE.md`, стр. 125 и 597

**Живого контракта на ЕГРН в материалах нет.** Есть только цепочка «файл выписки → Basis OCR → поля». Какие именно поля OCR извлекает — не зафиксировано. Известно, что у партнёра на первом экране залога есть распознавание ЕГРН (`mobile-appraiser-integration.md`, §4).

### 4.5. Клиент или менеджер — кадастр вручную

В кабинете `product.cadastral_number` — поле заявки, которое «часто `null`» (`_LK_KNOWLEDGE_BASE.md`, стр. 372). ЕГРН там числится как `missing` с пояснением:

> «Выписка ЕГРН — всегда `missing` («Нужен кадастр, не ЦП»)»
> — `_LK_KNOWLEDGE_BASE.md`, стр. 418

То есть кадастр приходит от клиента или из документа, но **не из цифрового профиля**: квартиры ЕСИА не отдаёт.

## 5. Чего не даёт ни один источник

| Сведение | Почему нет |
|---|---|
| Правообладатель, доля | Только ЕГРН. У МО и DaData этих полей нет |
| Обременения (ипотека, арест) | Только ЕГРН |
| Год постройки | МО отдаёт `bld.bldYear`, но он **может быть `null`** |
| Кадастр квартиры гарантированно | МО отдаёт `flat.cadNum` при условии `forceFlat`; иначе только кадастр здания |
| Живая проверка права запросом | Контракта СМЭВ ЕГРН в материалах нет |
| Список полей, извлекаемых OCR из ЕГРН | Не зафиксирован |

## 6. Что чему является источником истины

- **Стоимость для сделки** — официальный отчёт оценщика (`AppraisalPledgeCost`), не `stats.price`. Это разные величины: экспресс против официальной оценки. Расхождение между ними в документах отмечено как нормальное (`mobile-appraiser-integration.md`, §10).
- **Характеристики объекта** — МО Gate/Lookup.
- **Право и обременения** — выписка ЕГРН (в AS-IS файл + OCR).
- **Кадастр квартиры** — МО `flat.cadNum`, иначе из выписки ЕГРН, иначе ввод клиента.
- **Решение по клиенту** — не МО. Оценщик отвечает за цену объекта, а не за кредитное решение (это прямо разведено в скилле: «МО — цена объекта (lookup / express / отчёт), не решение по клиенту»).

## 7. Расхождение с макетом

Лабораторный экран «Карточка ЕГРН» **преувеличивает доступность данных**:

| Поле в макете | Откуда в реальности |
|---|---|
| Адрес | МО (нормализованный) |
| Тип | МО (`bld.bldType`) |
| Площадь / этаж | МО (`flat.area`, `flat.floor`) |
| Кадастр | МО `flat.cadNum` при `forceFlat`, иначе из выписки или ввод |
| **Правообладатель** | **ЕГРН, файл + OCR** |
| **Совпадение с ЕСИА** | вычисляется банком, источника нет |
| **Доля** | **ЕГРН, файл + OCR** |
| **Обременения** | **ЕГРН, файл + OCR** |

Макет показывает единый мгновенный ответ там, где в реальности два разных механизма: справочный запрос к оценщику и разбор документа от клиента.

## 8. Что нужно решить до реализации

1. **Есть ли у банка доступ к ЕГРН через СМЭВ** или через витрину ЦФТ? От этого зависит, можно ли получать право и обременения запросом.
2. **Что реально извлекает Basis OCR из выписки ЕГРН**: только адрес и площадь или ещё правообладателя, долю и обременения? Если только первое — проверку подтверждает человек.
3. **Надёжность кадастра квартиры от МО.** Стоит ли полагаться на `flat.cadNum` с `forceFlat` или источником считать выписку.
4. **Где по процессу проверять право и обременения** — до подачи заявки или на АПЗ, где комплект документов уже в работе и действует барьер паспорта сделки.
5. **Нужно ли тянуть кадастр из ЦФТ**, если клиент уже обслуживается в банке и объект там известен.

## 9. Что проверено, а что нет

**Проверено по файлам репозитория:**
- маппинг полей МО Lookup → заявка (`mobile-appraiser-integration.md`, §5.2) — прочитан дословно;
- состав ответа Gate и оговорки по `forceFlat`, блоку `flat` и `bld.cadNum` (`get_appraise_flat.md`) — прочитано;
- отсутствие ЕГРН-контракта и статус «файл + OCR» (`lk-external-integrations.html` стр. 578; `_LK_KNOWLEDGE_BASE.md` стр. 125, 597);
- «кадастр часто `null`» и ЕГРН как `missing` (база знаний, стр. 372, 418);
- роль DaData как подсказок адреса, не оценки (`lk-external-integrations.html`, стр. 382).

**Не проверено, требует подтверждения у ИТ и бизнеса:**
- фактический набор полей, который возвращает МО по нашему ключу (в документах — схема и живой ответ на дату, не наш контур);
- перечень полей OCR из выписки ЕГРН — в материалах **отсутствует**;
- наличие и условия доступа к СМЭВ ЕГРН — в материалах **отсутствует**;
- стадии официальной оценки (P1, MFMS) — спека MFMS в инвентаре источников помечена как отсутствующая.

## 11. Итог одной фразой

Характеристики и цена объекта берутся **запросом к Мобильному оценщику** (плюс DaData для адреса), кадастр квартиры — оттуда же при `forceFlat` или из выписки, а **право и обременения — только из выписки ЕГРН, которую в AS-IS приносит клиент и разбирает OCR**; живого запроса к ЕГРН в наших материалах нет.
